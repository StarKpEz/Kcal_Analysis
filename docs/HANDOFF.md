## 4. 设计决策与原因

- 保留静态 PWA：符合当前技术栈和设备条件，避免先承担原生重写、构建及签名成本。网页没有 HealthKit 接口，因此采用用户在手机生成精简 JSON、网页本地确认导入。
- 不用日常全量 Apple XML：用户全量导出体积很大；接收端只支持约定精简 JSON，不能把 XML/ZIP 直接当 JSON 导入。
- 手动记录与导入并存：保证数据导出尚未验收时也能使用；活动/静息、睡眠、体重可共同导入，训练暂以手填或日汇总文件兜底。
- 延时补齐：允许早晨同步后补前日能量和当日醒来的睡眠，近期范围重复导入按时间替换不累加；不把今日累计或日期已结束当作数据完整证明。没有后台拉取，也没有自动“已同步完整”状态。
- 不增加人工每日完成状态：用户不希望额外勾选；饮食保存即参与统计，但“有记录”不能证明全天没漏记。
- 体重完整历史：用户希望看到整个减脂期，默认全部历史；周/月/年、同范围统计和明细解决旧近14天展示不足。没有预测曲线、目标体重仪表盘或虚构插值。
- Apple 风格以用户偏好和现有行为为准；UI UX Pro Max 只作为检索参考，工具放在忽略目录，不成为网页运行依赖。后续开源复用需核对用途、许可证、离线及 iPhone 适配，不为了复用更换框架。
- 最终允许玻璃的范围只有浮动底栏。外层透出实际背景；内层椭圆保留几何形状但零填色、无描边/边缘阴影，以轻微亮度/对比度变化表现透镜。切换立即响应，短暂回弹；减少动态效果时停动画。它是 CSS/JS 适配，不是原生 Liquid Glass 或真实折射。
- 顶部文字模糊：用户反馈仅主屏幕应用模糊、Safari 正常，多次调整无效后明确停止处理；系统原因未证实，不重新投入修复，除非用户要求。

5. localStorage 不是云端或永久保存保证；Safari 与主屏幕应用可能呈现不同存储状态，具体行为尚无系统性验证。用户此前经历过数据恢复。不能以清网站数据、删除主屏幕应用或更换站点/路径作为常规排障手段；先核对完整备份。

7. v7 数据回退到旧网页有兼容风险；不能只回退页面而假定新快照仍可读。改数据模型或回退发布先设计兼容和可验证恢复路径。
