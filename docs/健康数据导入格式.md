# 健康数据导入格式

适用网页：**v2026-10-07.7**。入口：健康 → 导入健康 JSON。文件只在当前设备解析，不上传。

支持两条路径：已经汇总的 `kcal-health` v1/v2，以及手机快捷指令输出的 `kcal-health-samples` v1。苹果全量 XML 不适合日常导入，本版不读取 XML 或 ZIP。完整备份请在设置中恢复。

手机步骤：[快捷指令指南](shortcuts-guide.html)。当前环境为 Windows，无法运行苹果 macOS 快捷指令签名工具，因此提供手机手动创建方式，**没有一键安装链接，也尚未完成真实 iPhone 上的单位、分类与来源测试**。参考 [苹果词典与 JSON](https://support.apple.com/zh-cn/guide/shortcuts/apd43b69f337/ios)、[睡眠分期查询支持](https://support.apple.com/en-hk/101583)、[苹果签名工具](https://support.apple.com/zh-cn/guide/shortcuts-mac/apd455c82f02/mac)。未使用外部签名服务。

## 1. 已汇总的日记录

顶层：`app: "kcal-health"`、`version: 1` 或 `2`、带时区的 `exportedAt`、`days` 数组。每个日期最多一条，不能是未来日期。

每个对象包含 `date` 和至少一个类别。未出现的日期和类别保留现有记录。

| 类别 | 字段与单位 | 规则 |
| --- | --- | --- |
| `weight`（v2 新增） | `{kg: 71.8, measuredAt: "2026-10-05T08:00:00+08:00"}` | 数值型 kg，0.1–400；称重时间日期等于 date。每日一条，不补缺失日期 |
| `energy` | `active`、`basal`，数值型 kcal，两项都提供 | 去重后的日总量；训练热量不再加入消耗 |
| `training` | 会话数组：`id`、`type`、`durationMinutes`；可选 `startAt`、`distanceKm`、`energyKcal` | 当天完整列表；ID 稳定且唯一；空数组表示明确无训练；快捷指令指南暂不导出训练会话 |
| `sleep` | `asleepMinutes`；可选成对 `startAt`、`endAt`；可选 `stages` | 实际睡眠分钟；结束时间日期等于 date；清醒、卧床排除 |
| `sleep.stages` | `core`、`deep`、`rem`，数值型分钟 | v2 若提供分期，三项均须存在；合计不可超过实际睡眠。没有分期时省略，不填虚构的 0 |

睡眠阶段已知部分小于实际睡眠时，网页显示未细分分钟。旧版 v1 仍兼容部分分期字段。所有数值必须是 JSON 数字，不能是数字字符串。时间须带 Z 或 +08:00 等时区；归档日期以时间字符串的日期部分为准，跨时区旅行时需核对。

[日汇总示例](health-import-example.json) 使用虚构数据，仅用于测试，勿导入个人记录。

## 2. 快捷指令精简样本

顶层格式：

```json
{
  "app": "kcal-health-samples",
  "version": 1,
  "exportedAt": "2026-10-06T08:00:00+08:00",
  "from": "2026-10-01",
  "through": "2026-10-06",
  "samples": []
}
```

`from` / `through` 是最终归档日期的包含式范围。查询睡眠额外取前两天，以覆盖第一个归档日的前一晚；范围外的数据不写入。空数组不会清空数据，会提示无可导入记录。

| 每个样本的字段 | 含义 |
| --- | --- |
| `kind` | `weight`、`active`、`basal` 或 `sleep` |
| `value` | 体重/能量用数字；睡眠用分类文本或 HealthKit 分类整数，不是片段时长 |
| `unit` | 体重支持 kg、g、lb；能量支持 kcal、kJ、J、cal、Cal；中文单位支持千克/公斤/克/磅/千卡/大卡/千焦。必须对应真实数值；睡眠可省略 |
| `startAt` / `endAt` | 两项均提供，带时区的 ISO 时间；体重可用同一称重时间 |
| `source` | 非空来源名称，读取样本来源，不随意填统一标签 |

睡眠识别 Core / Asleep (Core) / 核心、Deep / 深度、REM、Awake / 清醒、In Bed / 卧床、Asleep / 未细分睡着，以及 HealthKit 的 0=卧床、1=未细分睡着、2=清醒、3=核心、4=深度、5=REM。未知文本明确报错，不推测；数值型分类可由快捷指令转成文本 `"3"` 等。

[样本示例](health-samples-example.json) 也是虚构测试数据。

### 体重汇总

- 同一日期取最后一次称重，保留称重时间；不平均、不求和、不补值。
- 同一时间不同体重报错，避免不确定来源被随意选择。
- 原有体重数值结构保持 `{日期: kg}`，来源和时间放入 `weightMeta`，绿色空心圆点线图继续使用数值。
- 手机历史查询示例从 **2026-09-23** 归档，保留此前记录；按个人历史调整起始日期。更早历史可另选范围，导入前仍有覆盖提示。

### 睡眠汇总

1. 完全相同样本去重。每类阶段内部重叠区间取并集，不叠加。
2. 连续片段间隔不超过 90 分钟归为同一段，卧床/清醒片段可连接夜间片段；按最后片段结束日期归档。同一天多段睡眠汇总为一份记录。
3. 实际睡眠取核心、深度、REM 和未细分睡着的时间并集；从未细分睡着区间扣除明确清醒片段。卧床不贡献实际时长。
4. 核心/深度/REM 互相重叠，或明确阶段与清醒重叠时，报错要求核对来源，不猜测优先级。
5. 未细分睡着与分期重叠时只统计一次。没有任何细分阶段则省略 stages，在网页显示“未提供”。
6. 多个来源的睡眠不自动混合；需在快捷指令里筛选一个来源。90 分钟分段是当前规则，不是苹果健康算法，长时间清醒、跨时区、来源差异时需核对归档。

尚不保存独立睡眠会话、不计算睡眠评分。导出窗口应完整，不能用少量片段覆盖完整日记录。

### 能量汇总

- 每类能量只接受一个来源。不同来源不相加；同一来源非完全重复重叠样本报错。不能声称单一来源一定等于健康 App 多来源日总量。
- 同一日活动与静息都有样本才更新能量；缺少一类则保留现有能量，预览提示，不补 0。
- 非重叠样本换算单位并求和。跨午夜样本按区间时长比例分配，并在预览提示。这是分配假设，应与健康 App 对照。
- 今天仍按累计显示，不当作完整全天消耗。

## 3. 导入、重复与迟到数据

建议早晨等待 Watch 同步后导出最近 7 天与今天，查询多取两天覆盖跨夜边界。首次只导体重测试，再增加能量和睡眠；核对一个完整日的总量与分期后再考虑自动运行。网页仍需手动选择文件并确认。

导入前预览每个日期和类别。相同或较旧导出跳过，新导出按日类别替换，不累加。体重若已有更晚称重也跳过较早称重，即使文件刚生成。较早手动记录被覆盖时明确提示；新手动记录晚于导出时间时保留。

所有类别通过同一快照一次保存。取消、解析失败、保存失败或其他窗口已更新时不会部分导入。最大 5 MB，最多 30,000 样本或 3,660 个日汇总。文件不会传到 GitHub 或服务器。

## 4. 完整备份兼容

完整备份升级为 **v7**，新增 `weightMeta`，包含来源、更新时间和称重时间。存储键继续使用 `kcal.data.v5`，保留并发快照比较；键名不代表快照版本。v5/v6 打开时只读取，首次成功保存升级为 v7，不删除旧键。

旧 v1–v6 备份没有的类别仍保留；旧备份覆盖体重时清除对应旧来源，避免来源时间与恢复数值不一致。v7 完整备份必须包含 weightMeta，即使为空。健康导入只修改所列日期和类别；完整备份恢复可合并或替换整类。回退旧网页前先导出 v7 完整备份，旧网页不会识别新版本快照。
