创建健康导出快捷指令

在 iPhone 上创建一次，以后运行并保存一个近期 JSON 文件，再回到网页导入。只查询体重、两项能量和睡眠，不导出全部健康历史。

本页是手机创建指南，不是一键安装链接。体重查询、JSON 保存和网页导入已通过用户的 iPhone 实际运行验证；能量、睡眠单位与分期值仍需首次运行核对。Windows 无法运行苹果的快捷指令签名工具。训练会话暂不包含在这个指令中，可继续手动记录。

先完成体重，再增加每日数据

先创建「导出历史体重」，确认成功后复制为「导出近期健康」。历史体重使用固定起始日期，例如 2026-08-01；请按自己的历史范围调整。查找健康样本的日期范围与文件的起始日期要对应，不用滚动的“最近30天”补全部历史。

健康 → 快捷指令 → 我的 iPhone 中的 JSON → 网页检查与确认

健康文件无需上传 GitHub。首次弹出权限时，只授权需要读取的健康项目。

1. 准备日期与变量

  1. 打开「快捷指令」→ 点击「＋」→ 命名为「导出历史体重」。
  2. 添加「日期」，选择当前日期。后续所有日期计算都明确引用这一个日期，称为「运行时间」。
  3. 添加「格式化日期」，输入「运行时间」，格式选择自定，填入下面的时间格式。把这个结果重命名为「导出时间」。
yyyy-MM-dd'T'HH:mm:ssXXX
  1. 再次「格式化日期」，输入仍为「运行时间」，自定格式 yyyy-MM-dd，结果命名为「今天」。
  2. 添加「文本」，内容例如 2026-08-01，结果命名为「起始日期」。添加一个「日期」，指定 2026 年 7 月 31 日 00:00，结果命名为「查询起点」。查询多取一天，最终文件按起始日期过滤；调整起始日期时一起调整查询起点。
  3. 添加「无」（Nothing），再添加「设定变量」，变量名「JSON片段」，输入明确选「无」。用它保存后面每条样本的 JSON 文本。

动作输出可通过点击变量重命名，也可紧接「设定变量」保存。取某个样本的详细信息时，每次都要明确选择「重复项目」，不要使用上一动作的结果。

2. 创建体重查询块

  1. 添加「查找健康样本」。类型选择体重（Body Mass / Weight），开始日期在「查询起点」之后、在「运行时间」之前。匹配方式选择所有条件，关闭数量限制。确认它查询健康 App 中的样本，而不是过滤上一步的「JSON片段」。
  2. 添加「重复每一项」，输入选择刚查到的健康样本。后面的操作放在「重复」和「结束重复」之间。
  3. 添加「获取健康样本的详细信息」→ 获取值，输入选「重复项目」，结果命名为「样本值」。再添加同一动作获取单位，输入仍为「重复项目」，结果命名为「样本单位」。
  4. 获取「重复项目」的开始日期，接「格式化日期」，用第一节的完整时间格式，结果命名为「开始时间」。
  5. 获取「重复项目」的结束日期，同样格式化，命名为「结束时间」。
  6. 获取「重复项目」的来源，命名为「样本来源」。
  7. 添加「字典」，按下表建立字段。英文键名逐字填写；右侧的变量应使用快捷指令的变量标签，不能输入变量名字当普通文字。iPhone 实测搜索“字典”；搜索“词典”可能只得到“显示定义”。
键字段类型值
kind文本weight
value数字「样本值」变量
unit文本「样本单位」变量
startAt文本「开始时间」变量
endAt文本「结束时间」变量
source文本「样本来源」变量
  1. 添加「从输入中获取文本」，输入明确选上面的字典。再添加「添加到变量」，把这段文本添加到「JSON片段」。
  2. 保留「结束重复」。不要在循环外重新设定「JSON片段」，否则会丢掉前面的样本。

单位跟着数值一起导出，网页支持 kg、g、lb，自动转换为 kg。不要把实际是磅的数值标成 kg。同一天多次称重取最后一次。

3. 包装并保存 JSON

  1. 在「结束重复」之后，添加「合并文本」，输入选「JSON片段」，分隔符选择自定，填一个英文逗号 ,。结果命名为「样本文本」。
  2. 添加「文本」，粘贴下面模板。删掉四个 【…】 占位符，逐个插入对应的变量标签。导出时间与两项日期外面的双引号保留；样本文本外面不能加双引号。
{
  "app": "kcal-health-samples",
  "version": 1,
  "exportedAt": "【导出时间】",
  "from": "【起始日期】",
  "through": "【今天】",
  "samples": [
    【样本文本】
  ]
}
  1. 添加「从输入中获取字典」，输入选择刚才的完整文本。这一步检查 JSON 是否能解析；发生错误时先修正模板和变量。
  2. 添加「从输入中获取文本」，输入选择刚解析的完整字典。添加「设定名称」，名称填 kcal-health-【今天】.json，其中今天插入日期变量。
  3. 添加「存储文件」，输入选刚命名的文件，开启「询问存储位置」。运行后保存到我的 iPhone中的一个文件夹。
  4. 回到网页「健康 → 导入健康 JSON → 选择 JSON 文件」。先检查体重日期、数值，再确认导入。

首次先运行体重版。单条样本应是词典对象，不是加了引号的长字符串；日期要带 +08:00 等时区，value 要是数字。文件中的任何测试数值都不应导入真实记录。

4. 扩展为每日能量与睡眠

  1. 复制已成功的体重指令，重命名「导出近期健康」。
  2. 把固定「起始日期」改为：「调整日期」→ 从运行时间减去 7 天 → 格式化为 yyyy-MM-dd。把查询起点改为：运行时间减去 9 天。额外查询两天是为了取齐第一个归档日的跨夜睡眠。
  3. 把第二节整个查询与循环块复制三次，放在原体重块之后、第三节「合并文本」之前。四个块共用「JSON片段」，每次查找都查询健康 App，且循环的详细信息都引用各自的「重复项目」。
健康类型kind 文本value 类型
体重weight数字
活动能量 / Active Caloriesactive数字
静息能量 / Resting Caloriesbasal数字
睡眠 / Sleepsleep文本（分期值）

能量读取值和实际单位（支持 kcal、kJ 等）。睡眠读取的是「值」，不是「时长」，保留核心、深度、REM、清醒、卧床或未细分睡着的分类；睡眠块删去获取单位动作和字典的 unit 字段。

在能量与睡眠的「查找健康样本」里，增加来源条件，每类选一个你实际使用的来源。睡眠通常选佩戴的 Apple Watch。第一版不会混加多个设备的样本；网页检测到多个来源会提示调整筛选。单一来源的能量也要与健康 App 对照，不能默认等同于它的多来源日总量。

首次测试时，可临时在获取睡眠「值」后加「快速查看」，确认结果是 Core、Deep、REM 或对应中文分类。若结果无法识别，网页会显示原始值并停止导入，不猜测分期。动作中文名称可能随 iOS 版本变化，可用“健康样本”“字典”“合并文本”搜索。

5. 日常使用与核对

  • 建议起床后，待手表数据在健康 App 中出现，再手动运行近期指令。昨天的能量、今天醒来的睡眠一起导入；今天能量仍是累计。
  • 查看网页预览中的体重和睡眠日期。相邻睡眠样本间隔不超过 90 分钟归为同一段，使用最后片段结束日期；长时间清醒或多段睡眠可能需要核对归档。
  • 相同睡眠时间段只统计一次，实际时长排除清醒和卧床；未细分睡着不重复叠加分期。没有细分数据时展示“未提供”。睡眠评分暂不计算。
  • 每个导出窗口应包含范围内的完整样本，关闭数量限制。缺少某项权限或只导出部分片段时，先不要覆盖已有日汇总。
  • 重复导入同一文件会跳过。重新运行导出后可补齐晚同步的数据；之前日期和没有出现在文件中的类别继续保留。

首次至少核对一个完整日：体重、活动能量、静息能量、实际睡眠、核心、深度、REM。源数据一致后，再考虑定时运行；网页导入目前仍需手动确认。
