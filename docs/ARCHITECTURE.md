# 当前架构

核对日期：2026-10-18。本文描述实际本地实现；发布与阶段进度见 [HANDOFF.md](HANDOFF.md)，长期约束见 [AGENTS.md](../AGENTS.md)。修改架构时同步本文，不把旧规划当作当前实现。

## 项目边界与运行方式

Kcal_Analysis 是独立 Git 仓库，运行于静态 HTTP/HTTPS，部署到 GitHub Pages；无 package.json、打包步骤、后端、账号或第三方网页运行库。父目录 LifeTracker 的 Expo 记账工程另行保留。

应用使用原生 HTML/CSS/JavaScript、SVG、localStorage、Service Worker。离线与 SW 检查需要 localhost 或 HTTPS，不能以 file:// 打开结果代替。Node 仅用于开发工具；两项浏览器检查另需 Playwright 和 Chrome。

饮食识别使用用户复制到 DeepSeek、再粘贴回答的桥接方式，网页不接收照片、不直连 AI API。Apple 健康通过精简 JSON 文件或粘贴导入，不直接调用 HealthKit；没有后台同步服务。

## 模块与依赖

| 文件 | 职责与关系 |
| --- | --- |
| `index.html` | DOM、基础 CSS、一个内联主脚本；饮食解析、日期、路由、健康模型、SVG 图表、存储、导入恢复和更新入口 |
| `app.css` | 在基础 CSS 之后加载，统一正式版视觉及适配 |
| `navigation.js` | 根据底栏链接的 `aria-current` 更新单个 `#tabGlassLens`；只负责视觉反馈，不负责路由和存储 |
| `sw.js` | 缓存完整应用壳，HTML 网络优先、其他同源静态资源缓存优先；安装成功后接管 |
| `manifest.webmanifest`、`icons/` | 主屏幕安装元数据和图标；当前使用 v3 PNG 图标 |
| `_tools/` | 通过 Node assert/vm 检查提取出的应用逻辑，另有浏览器检查与预览生成器 |
| `preview/` | 独立预览外壳、生成页面、草案 CSS/动画和内存演示数据，不是第二份业务实现 |

主路由为 `#/diet`、`#/health`，健康详情为 `#/health/energy`、`#/health/weight`、`#/health/training`、`#/health/sleep`、`#/health/import`。路由实现仍在主脚本；设置作为独立覆盖页面处理。栏目共用所选日期，保留栏目/详情滚动位置；刷新默认选择今天。

## 保存与恢复

当前持久化键为 `kcal.data.v5`，其中快照 **version 为 7**；键名不表示数据版本。

| 快照字段 | 用途 |
| --- | --- |
| `entries` | 日期 → 餐次 → 食物条目 |
| `settings`、`body` | 用户目标、应用设置、身体档案与公式参数 |
| `weight`、`weightMeta` | 日期 → kg，以及称重时间、来源、更新时间 |
| `burn` | 每日活动/静息能量、来源、更新时间 |
| `training`、`sleep` | 每日训练会话与睡眠汇总/分期及来源 |
| `completion` | 旧版完成状态兼容字段，当前不要求每日勾选，也不用于能量计算 |
| `meta` | 备份时间等元数据 |

启动时优先读取完整快照，可识别 v5/v6/v7；没有完整快照时读取原有 `kcal.entries.v1`、`kcal.settings.v1`、`kcal.meta.v1`、`kcal.body.v1`、`kcal.weight.v1`、`kcal.burn.v1`。旧键不删除，旧快照首次成功保存升级为当前版本。

写入流程：输入校验/归一化或导入预览 → `commitData(patch)` → 与加载时原始快照比较 → 单次 `localStorage.setItem` → 更新已提交内存快照。写入失败回滚内存；其他窗口更新时停止写入并要求重新加载；读取异常时阻止普通保存，提供原始恢复文件导出。

`buildBackup()` 导出完整 v7 文件；`validateBackup()` 兼容既有 v1–v7 备份及历史格式。恢复支持合并/按文件包含的整类覆盖，缺少的类别保留，取消和失败不得部分恢复。原始故障恢复文件不同于正常备份。浏览器只能确认已发起下载，文件是否保存需用户在设备上核对。

## 健康导入与计算

`parseHealthJSON()` 接收 `kcal-health` v1/v2 日汇总，或先经 `summarizeHealthSamples()` 转换的 `kcal-health-samples` v1；`healthImportPlan()` 生成覆盖/跳过预览，确认后一次保存。完整协议、限制和样例见 [健康数据导入格式.md](健康数据导入格式.md)。

本地待发布版 v2026-10-18.1 新增 `summarizeHealthEnergy()`：将 `kcal-health-energy` v1 的两类日期/数值列与少量午夜边界候选样本转换为同一日汇总管线。按真实日期匹配，校验数量、单位、来源、午夜与时区，进行边界时长分配；缺少日汇总或任一侧边界则保留已有日期，不假定为零。保存计算小数，预览同时显示日期范围和舍去小数的活动/静息对照值；不改变全局 `N()` 格式化或既有数据模型。能量详情通过普通hash链接进入共用导入路由，保存成功后显示本机已保存提示。真实文件解析和虚构文件的浏览器完整导入流程通过；尚待发布与真实iPhone确认导入，不能将测试上下文的保存称为用户手机已保存。

- 较旧/相同导出不覆盖较新记录；新导出按日类别替换，不累加。体重额外比较称重时间，每日取最后一次真实测量。
- 样本导入仅支持 weight/active/basal/sleep，不含训练会话。每类能量及睡眠要求单一来源；重叠或来源歧义不能静默混加。睡眠取实际睡着区间并集，排除清醒/卧床，按结束日归档；同日多段汇总，尚无独立午睡会话。
- 健康能量总量是活动 + 静息；不重复叠加训练、活动系数或食物热效应。没有健康能量时可用 BMR × 活动系数估算，并与健康录入分开标识。
- 今天按累计展示，不计算全天记录差额；历史有饮食与消耗才比较，缺失不补零。历史日期结束不代表 Watch 数据已完整同步。
- 体重图表默认全部历史，可选周/月/年；真实日期间隔和空心圆点保留，缺测不补值。代谢趋势推算另用近 28 天窗口，不受图表显示区间替代。

原始样本不长期保存到本地快照，只保留归一化日记录及元数据。导入文件在设备浏览器内解析，不上传；后续若修改聚合算法，可能需要重新导出原样本，不能假定现有快照足以重算。

## 预览、更新与测试依赖

`node _tools/build-design-preview.js` 从正式 `index.html` 生成 `preview/app.html`，排除正式外部样式/导航脚本及版本更新代码，改接 `preview/demo.js` 的内存存储，再载入独立主题和导航脚本。`preview/index.html` 的 iframe 只授予 `allow-scripts allow-downloads`，无同源权限；复制页无 manifest/SW 注册，禁止外部连接。不要手改生成页面。

生成器依赖一个内联主脚本和“版本与更新”分区边界；逻辑测试还依赖 `TEST-EXTRACT-*` 及函数边界。拆模块时同时更新依赖方，不可仅删标记。

正式版资源版本与 SW `SHELL` 必须一致；静态资源采用缓存优先，因此改样式/脚本不能只改文件而不处理版本。完整应用壳缓存成功才执行 `skipWaiting`，新 worker 激活后清旧缓存；失败安装保留旧 worker。

具体检查命令和按改动选择测试的规则见 [AGENTS.md](../AGENTS.md)。测试使用虚构数据和独立浏览器上下文，不能证明真实 iPhone 的系统材质、主屏幕顶部渲染或健康来源聚合正确。
