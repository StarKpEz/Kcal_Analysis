# 饮食 · 拍照算热量

一个自包含的网页应用（PWA）：**拍照或描述你这一餐，自动算出热量与蛋白质 / 脂肪 / 碳水**，并把每天的摄入记录在手机本地。

- 🌐 在线使用：**https://starkpez.github.io/Kcal_Analysis/**
- 📱 手机浏览器打开后「添加到主屏幕」，就像原生 App 一样全屏运行
- 🔌 加载过一次后**完全离线可用**（记录、计算、改克数都不联网）
- 🔒 **零依赖、零外链、零账号**，所有记录只存在你自己的浏览器里

## 怎么用

因为采用「**粘贴桥接**」方案，不需要 API Key、不产生任何费用。
**照片直接在 DeepSeek 里上传** —— 本应用不需要、也不接触照片，因此不需要任何相机 / 相册权限：

1. 先选**餐次**（早餐 / 午餐 / 晚餐 / 加餐，默认按当前时间自动选中）
2. 在文本框写一句描述（可选，但**对准确度帮助很大**），例如「一碗米饭约 200g、两块红烧肉，油比较多」
3. 点 **① 复制文字并打开 DeepSeek** —— 会复制提问文字并尝试唤起 DeepSeek
   （想只复制不跳转，用旁边的 **仅复制文字**）
4. 在 DeepSeek 里**上传这一餐的照片** → 粘贴 → 发送
5. 把回答**整段复制**回来 → 点 **② 粘贴回答**
6. 自动解析并记入第 1 步选定的餐次，累加到今日总计

### 关于「打开 DeepSeek」按钮

DeepSeek **官方目前没有公开的 URL scheme**（社区里还在提这个需求），所以这个按钮采用**顺序尝试**策略：

1. 你在设置里填的自定义 scheme（如果填了）
2. `https://chat.deepseek.com/` —— 通用链接，装了 App 的系统通常会把它交给 App 打开
3. 都不行就提示你手动切换

如果哪天真机实测出可用的 scheme（例如 `deepseek://`），填进 **⚙️ → DeepSeek 唤起链接** 即可优先使用。

## 界面风格

采用 **iOS 设计语言**：

- **系统色**：深色模式用 iOS 系统色变体（systemGreen/Blue/Yellow/Orange），浅色模式自动切换为对应亮色版本（跟随系统外观）
- **深色模式为纯黑底**（`#000000`），OLED 屏幕上更省电、层次更明显
- **分组列表与轻量卡片**：设置采用不透明的独立页面，按目标、身体数据、备份和应用分组；保存操作固定在顶部。
- **统一线条图标**：设置、返回、关闭及设置页操作不使用圆形灰底，导航按钮保持至少 44 × 44 CSS px 的触摸区域。
- **交互层级**：主要保存操作突出，清空操作独立放置并使用危险色；键盘焦点可见，设置关闭后返回原入口。
- 深浅外观、减少动态效果、输入标签与底部安全区适配。暂不引入 Liquid Glass；记录弹窗沿用普通背景模糊。
- 设计依据：[Apple HIG — Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)、[Settings](https://developer.apple.com/design/human-interface-guidelines/settings)、[Layout](https://developer.apple.com/design/human-interface-guidelines/layout)。无底色按钮是本项目按用户偏好选择的样式，不声称是最新 HIG 对所有按钮的要求。

## 健康页与底部导航（2026-10-07.5）

底部固定 **饮食 / 健康** 两个栏目，采用不透明背景、线条图标和文字，所选栏目为蓝色，适配底部安全区。健康详情保留底栏；设置和临时表单覆盖底栏。参考 [Apple HIG — Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)，本项目暂不使用 Liquid Glass。

健康页展示所选日期的活动能量、静息能量及体重。能量卡片进入原有代谢详情，体重卡片直接定位到记录区，保留已有数据和计算口径。缺失能量显示“—”，0 是有效记录；体重显示该日或此前最近的记录，并注明日期，不使用未来称重。

两个栏目共用所选日期；切换时保留各自滚动位置和健康详情位置。支持浏览器前进、后退与 `#/health`、`#/health/energy`、`#/health/weight` 链接。刷新沿用原有逻辑选择今天。训练、睡眠仅显示“暂未接入”，尚无表单或健康数据导入。

验证：四组 Node 回归测试通过；桌面浏览器以 393×852 和 320×568 验证切换、日期共享、详情返回、能量保存与体重入口，[健康页预览](docs/previews/health-navigation-2026-10-07.jpg)使用虚构测试数据。顶部模糊问题按用户决定停止继续调整。

## iOS 主屏幕顶部模糊兼容（2026-10-07.4）

真机反馈：v2026-10-07.3 在 iOS 27.0.1 的主屏幕应用中仍模糊，同网址 Safari 正常，因此上一版的布局和状态栏调整没有解决该问题。

本版仅在 `navigator.standalone === true` 且支持 iOS WebKit 属性时启用一个 12px 高的独立固定颜色边界。它使用页面深浅背景色，空元素的 `background-clip: text` 不绘制遮盖，`pointer-events: none` 不拦截点击，`aria-hidden` 不进入辅助阅读；设置和消耗页打开时保持它参与渲染。不增加空白、不移动按钮、不写入记录，也不需要删除主屏幕图标。

依据：[WebKit 的边缘颜色采样实现](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/page/LocalFrameView.cpp)和 [WKWebView 的系统滚动边缘处理](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKWebView.mm)。固定/粘性元素、尺寸和样式颜色会参与采样，边缘颜色视图影响系统效果的显示。此处据源码选择兼容方法，当前主分支不等于设备内的具体 WebKit 构建；非公开行为可能随系统更新改变，**实际是否消除模糊需 iOS 27.0.1 真机确认**。

验证：三组现有 Node 回归测试通过；普通浏览器不启用兼容元素。使用仅本地的测试页面强制启用同一组样式并把背景设为亮粉色，确认没有色块遮盖、点击穿透正常、设置与消耗页打开后元素不被置为 inert、保存和滚动正常。此测试检查布局和交互，不模拟 iOS 的系统模糊。正式页面 [393×852 预览](docs/previews/settings-ios-compat-2026-10-07.jpg)使用虚构数据。

验证：三组现有 Node 回归测试通过；桌面浏览器在 393×852 下验证导航栏不随表单滚动、保存和取消正常、重新进入设置回到顶部，在 320×568 下验证顶部按钮未被裁切且点击高度为 44 px。预览使用虚构测试数据，见 [设置顶部预览](docs/previews/settings-header-2026-10-07.jpg)，不代表 iPhone 真机结果。

## 长期记录与完整备份（2026-10-07.2）

饮食、体重和健康能量长期保留，不再自动删除 30 个日期之前的饮食。月历可访问历史月份，图表显示范围不影响存储范围。

不要求每天勾选完成状态。饮食保存后直接参与记录统计；没有条目显示“未记录”，不按零摄入处理。有条目不代表全天已记全，差额和趋势均说明漏记的影响。今天的健康能量作为日内累计，不展示全天差额。

设置中的 **备份全部数据** 导出 v5 JSON，包含饮食、身体档案、体重、健康能量、目标和备份元数据。旧版 `completion` 字段仅为恢复兼容继续保留，不再影响统计。CSV 是饮食明细，不能代替完整备份。应用提示“已发起导出”，请在“文件”App 确认文件已保存。

恢复前显示日期范围与各类记录数量，可取消、合并或覆盖。完整 v5 备份可以替换空类别；旧版 v1–v4 缺少的类别保留。合并时保留已有饮食，同一天体重和能量以备份为准；重复恢复不会重复增加相同记录，同一餐多份相同食物也保留份数。

全部数据一次写入本地快照，取消或写入失败不会部分恢复。首次成功保存自动迁移原有数据，原有存储键不删除。读取异常时停止普通保存，可导出原始恢复文件用于排查，避免覆盖原始内容。新版后续数据保存在 v5 快照；旧版本代码看不到新版后续新增记录，版本回退应先完整备份。

## 代谢与消耗

底部“健康”→“健康能量”进入代谢详情。先选择日期，再录入 Apple 健康中同一天的 **活动能量** 和 **静息能量**，两项均需填写，0 区别于空白。网页目前不会直接读取 Apple 健康。

- 健康能量总消耗 = 活动 + 静息，不另加训练热量、活动系数或食物热效应。
- 未录入时，使用 BMR × 活动系数估算全天消耗，不再添加摄入的 10%。BMR 使用 Mifflin-St Jeor；填写体脂率时改用 Katch-McArdle，准确性取决于输入与测量。
- 今天不展示全天差额。历史日期有饮食与消耗时直接计算记录差额，公式消耗单独标为估算；历史手动能量应录入全天累计，可随时补录修正。
- 14 天统计截至所选日期，已记录摄入、已录入健康能量、同日配对以及公式估算分别计算，显示实际覆盖天数；平均值不含今天，缺失日不当成零，不声称记录已完整。
- 参考摄入基于身体档案的全天公式估算，不随半天的健康能量改变。原有参考下限生效后，显示的缺口与最终目标保持一致。参考下限不保证个人适用，不自动修改设置。
- 取消单日缺口外推“预计每周减重”。近 28 天体重回归趋势与已记录饮食可提供粗略消耗参考：至少 4 次称重、跨度至少 14 天、称重区间每天均有饮食条目。漏记会影响结果；它不是实测 TDEE，也不保证比手表或公式更准。

## 本地数据与备份

所有记录只存在当前浏览器/PWA 的本机存储中，无账号同步或云端备份，受浏览器存储空间限制。Safari 与主屏幕网页应用的数据可能不共享；删除图标、清理浏览器数据或换手机前，先在当前使用的应用中导出完整 JSON 并确认文件已保存。

## 主页面结构

底部切换 **饮食 / 健康**，顶部日期和日历共用。饮食页从上到下为 **摄入热量 → 饮食记录 → 营养摄入**；健康页为 **健康能量 → 体重 → 训练 / 睡眠占位**。
记录保存后即可查看；食物输入在弹窗里，能量和体重复用健康详情中的表单，备份和管理操作在设置页。

**顶部日期就是统计入口**（参考 iOS 饮食 App）：

- **点击「今天 / 10月2日」**在两种视图之间切换：
  - **折叠 = 周视图**：截至所选日期的 7 天，每格「星期 + 小圆环 + 日期号」，点某天切过去
  - **展开 = 整月日历**：‹ › 翻月份（不能翻到未来），每格小圆环表示当天热量完成度，点某天切过去并自动收起
- 右侧「今天」按钮一键回到今天
- 圆环配色：🔴 超标 · 🟢 达标 · 🟠 偏少 · 🟡 很少 · 灰 未记录
- 健康页使用纯日期日历，隐藏饮食热量圆环，避免误作健康记录完成度。

**饮食记录**（早餐 / 午餐 / 晚餐 / 加餐四行）：

- 每行显示该餐热量，右侧 **＋ 点开记录弹窗**（自动预选这一餐）
- **点这一行可展开**看该餐的条目，可改重量（按比例重算）、删除
- 空餐次展开后提示「点右上角 ＋ 添加」

**营养摄入**：三色圆环（蛋白质 / 脂肪 / 碳水）+ 图例，跟随所选日期实时更新。

## 补记历史日期

「记录一餐」卡片顶部有**日期选择器**：

- 用 **‹ ›** 逐日前后切换，或点日期框直接选日期（范围：历史日期，不能选未来）
- **「今天」按钮**一键回到今天（已是今天时显示绿色选中态）
- 切到历史日期后，标题变成「**补记 · 10月2日**」，记录写入那一天
- 上方的今日总计卡片与圆环会一起切到该日期，方便对照补记
- 「导出今日 CSV」「清空今日」也随之作用于**所选日期**

## 从对话 / 文档导入记录

如果记录散落在 DeepSeek 对话或某个文档里，「数据与备份」卡片 → **📋 从对话/文档导入记录**，
把内容整段粘进去 → **先检查**（会告诉你解析到几天几条）→ **导入**。

支持的写法（日期单独一行，或写在标题/正文里都可以）：

```
2026-10-01
早餐：鸡蛋 50g 78kcal 蛋白质6g 脂肪5g 碳水1g
午餐 | 牛肉面 | 450g | 680kcal | 蛋白质28g | 脂肪22g | 碳水88g
2026-10-02
米饭 200g 232kcal 蛋白质5g 脂肪0.6g 碳水51g
```

- **日期**：`2026-10-01`、`2026/10/1`、`2026年10月1日`、`10月1日`（沿用前面出现过的年份）、`## 2026-10-01` 都认
- **餐次**：早餐/早饭/早点、午餐/午饭/中餐、晚餐/晚饭、加餐/夜宵/零食/下午茶，中英文皆可；
  分隔符是冒号、竖线还是空格都行；**没写餐次的行会归入「未分餐」**，之后可用餐次下拉归位
- **每行食物**：支持 `名称 | 重量 | 热量 | 蛋白质 | 脂肪 | 碳水`、空格分隔、Markdown 表格行
- **安全设计**：**没有日期就一条都不导入**，避免把对话里的闲聊误写成记录；
  「合计」行不会重复计入；导入前会先给你看解析结果
- 导入时可选 **合并**（保留现有数据、自动跳过重复条目）或 **覆盖**（完全替换）


## 三餐分开记录

- 顶部有 **4 个餐次按钮**，点一下就切换当前餐次；按钮上直接显示该餐已记录的 kcal
- 默认餐次按时间自动判断：10 点前 → 早餐，15 点前 → 午餐，21 点前 → 晚餐，之后 → 加餐
- **今日总计卡片**里有一行「各餐热量」小结，一眼看到三餐分布
- **今日明细**按餐次分组，每组标题带该餐的小计（热量 + 三大营养素）
- **点分组标题可折叠 / 展开**该餐明细（折叠后标题仍显示小计，不会漏看数字）
- **每条记录都有「餐次」下拉菜单**，改一下就自动移动到对应分组 ——
  旧版本那些进「📋 未分餐（旧记录）」的记录，就是靠这个逐个归位到早/午/晚餐
- **导出的 CSV** 含「餐次」列、每餐小计和全天合计
- 旧版本（未分餐）的历史记录会自动归入「📋 未分餐（旧记录）」分组，**不会丢失**

### 其他功能

| 功能 | 说明 |
|---|---|
| 改重量 | 直接改某条的克数，该条的热量和三大营养素**按比例自动重算**，总计同步更新 |

| 历史 | 长期保存，可通过月历浏览与补记 |

## 文件说明

| 文件 | 作用 |
|---|---|
| `index.html` | 整个应用（界面 + 逻辑 + 解析器），单文件自包含 |
| `manifest.webmanifest` | 让「添加到主屏幕」显示正确的应用名和图标 |

## 隐私与准确性

- **照片不经过本应用**：直接上传给 DeepSeek，本应用不读取、不上传、不保存任何照片
- 所有记录存在浏览器 `localStorage`，**换手机或清理浏览器数据会丢失**，重要数据请用「备份全部数据」导出 JSON
- AI 对中餐分量的估算是**估算**，误差约 ±20~30%，红烧、油炸类尤其容易低估；混合菜品（盖浇饭、麻辣烫）建议配合文字描述

## 更新应用

改完 `index.html` 后提交，等 1~2 分钟 GitHub Pages 自动重新部署。

**手机上怎么拿到新版**（针对 iOS 主屏幕应用，它没有地址栏也没有下拉刷新）：

1. **正常联网打开应用即可** —— Service Worker 对 HTML 采用网络优先策略，联网时每次打开都是最新版，不需要任何手动操作
2. 若仍看到旧版：打开右上角 **设置 → 检查更新**，按提示确认即可
3. 极端情况下（应用图标缓存、iOS 顽固缓存）：先在目前使用的应用中导出完整 JSON，并确认文件已保存，再考虑重新添加图标；不能保证重新添加后原存储仍在

应用内 **设置页底部显示当前版本号**，可用来确认是否已更新到最新版。
