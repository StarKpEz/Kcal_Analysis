# 饮食 · 拍照算热量

一个自包含的网页应用（PWA）：**拍照或描述你这一餐，自动算出热量与蛋白质 / 脂肪 / 碳水**，并把每天的摄入记录在手机本地。

- 🌐 在线使用：**https://starkpez.github.io/Kcal_Analysis/**
- 📱 手机浏览器打开后「添加到主屏幕」，就像原生 App 一样全屏运行
- 🔌 加载过一次后**完全离线可用**（记录、计算、改克数都不联网）
- 🔒 **零依赖、零外链、零账号**，所有记录只存在你自己的浏览器里

## 怎么用

因为采用「**粘贴桥接**」方案，不需要 API Key、不产生任何费用。
**照片直接在 DeepSeek 里上传** —— 本应用不需要、也不接触照片，因此不需要任何相机 / 相册权限：

1. 先选**餐次**（早餐 / 午餐 / 晚餐 / 加餐，默认按当前时间自动选中）
2. 在文本框写一句描述（可选，但**对准确度帮助很大**），例如「一碗米饭约 200g、两块红烧肉，油比较多」
3. 点 **① 复制文字并打开 DeepSeek** —— 会复制提问文字并尝试唤起 DeepSeek
   （想只复制不跳转，用旁边的 **仅复制文字**）
4. 在 DeepSeek 里**上传这一餐的照片** → 粘贴 → 发送
5. 把回答**整段复制**回来 → 点 **② 粘贴回答**
6. 自动解析并记入第 1 步选定的餐次，累加到今日总计

### 关于「打开 DeepSeek」按钮

DeepSeek **官方目前没有公开的 URL scheme**（社区里还在提这个需求），所以这个按钮采用**顺序尝试**策略：

1. 你在设置里填的自定义 scheme（如果填了）
2. `https://chat.deepseek.com/` —— 通用链接，装了 App 的系统通常会把它交给 App 打开
3. 都不行就提示你手动切换

如果哪天真机实测出可用的 scheme（例如 `deepseek://`），填进 **⚙️ → DeepSeek 唤起链接** 即可优先使用。

## 界面风格

采用 **iOS 设计语言**：

- **系统色**：深色模式用 iOS 系统色变体（systemGreen/Blue/Yellow/Orange），浅色模式自动切换为对应亮色版本（跟随系统外观）
- **深色模式为纯黑底**（`#000000`），OLED 屏幕上更省电、层次更明显
- **大圆角卡片 + 柔和投影**，去掉硬边框，贴近 iOS 的分组列表观感
- **毛玻璃弹出层**：`backdrop-filter: saturate(180%) blur(22px)`，并用 `@supports` 守卫 —— 不支持毛玻璃的浏览器自动回退成较实的遮罩，不会因为透出内容而影响阅读
- **胶囊按钮与分段控件**（日/周/月页签即 iOS Segmented Control 样式）
- 输入框聚焦时显示**绿色发光环**（iOS focus ring）
- 底部安全区适配 + Toast 悬浮提示（同样带毛玻璃）

## 代谢与消耗（减脂热量）

主页面底部的 **「代谢与消耗」** 卡片是入口，点进去是第二个页面。目前用的是**公式估算**
（Apple 健康真实数据的接入留在后续，方案见 `docs/代谢与消耗-调研与规划.md`）。

**身体数据**（⚙️ 设置里填）：性别、出生年份、身高、体脂率（可选）、日常活动水平。

**BMR 自动择优**：

| 情况 | 用哪个公式 | 说明 |
|---|---|---|
| 填了体脂率 | **Katch-McArdle** `370 + 21.6 × 去脂体重` | 最准 |
| 没填体脂率 | **Mifflin-St Jeor** | 通用最准 |

**TDEE** = BMR × 活动系数（久坐 1.2 / 轻度 1.375 / 中度 1.55 / 高度 1.725 / 极高 1.9）。

**能量平衡**（按所选日期）：

```
总消耗 = 静息 + 日常与运动 + 食物热效应(摄入的 10%)
缺口   = 总消耗 − 饮食摄入
预期减脂 ≈ 缺口 × 7 ÷ 7700      （1 kg 脂肪 ≈ 7700 kcal）
```

**目标摄入建议**：缺口取 `TDEE × 20%`，限制在 300~750 kcal，且**不低于安全下限**
（男 1500 / 女 1200 kcal）；被下限抬高时会明确提示。

**用体重反推「实际 TDEE」** —— 比公式更准，因为用的是你自己的真实数据：

```
实际 TDEE = 期间平均摄入 + 掉掉的体重 × 7700 ÷ 天数
```

- 需要 **≥7 天跨度**（至少两条体重记录：首尾各一），且期间**至少一半天数有饮食记录**
- 跨度超过 42 天会提示参考性下降
- 掉秤时实际 TDEE 高于平均摄入；增重时低于（方向有测试守着）
- 结果会与公式估算值对比，差值较大时提示「活动水平设置可调整」

**体重记录**：在第二屏直接输入保存；显示最新值、较首次变化、已记录天数，以及近 14 天趋势。

**近 14 天趋势**：双色柱对比「摄入（蓝）vs 消耗（橙）」，并给出 14 天平均值。

## 数据安全（重要）

> ⚠️ **所有数据只存在这台手机的浏览器里**（`localStorage`），与账号无关、不上云。
> **删除主屏幕图标、清理浏览器数据、换手机、重装系统都会导致数据丢失。**

而且 iOS 上有个容易踩的坑：**Safari 打开的网页**和**添加到主屏幕的图标**是**两个完全独立的存储容器**，
在其中一个里记录的数据，另一个里看不到。

因此请务必定期备份：

| 操作 | 位置 | 说明 |
|---|---|---|
| **⬇️ 备份全部数据** | 「数据与备份」卡片 | 导出 JSON 文件，含全部历史记录与目标设置 |
| **⬆️ 恢复备份** | 「数据与备份」卡片 | 选 JSON 文件导入，可选「合并」或「覆盖」 |

- 备份文件建议存到「文件」App、或发给自己（微信/邮件）
- 导入时：**合并**会保留现有数据并跳过重复条目（同名+同热量视为同一条）；**覆盖**则完全替换
- 应用会自动记录上次备份时间，超过 7 天未备份会在打开时提醒一次

## 主页面结构

从上到下：**顶部日期 + 日历 → 摄入热量 → 饮食记录 → 营养摄入**。主页面**只呈现数据**，
所有输入与管理操作都在弹窗里。

**顶部日期就是统计入口**（参考 iOS 饮食 App）：

- **点击「今天 / 10月2日」**在两种视图之间切换：
  - **折叠 = 周视图**：最近 7 天，每格「星期 + 小圆环 + 日期号」，点某天切过去
  - **展开 = 整月日历**：‹ › 翻月份（不能翻到未来），每格小圆环表示当天热量完成度，点某天切过去并自动收起
- 右侧「今天」按钮一键回到今天
- 圆环配色：🔴 超标 · 🟢 达标 · 🟠 偏少 · 🟡 很少 · 灰 未记录

**饮食记录**（早餐 / 午餐 / 晚餐 / 加餐四行）：

- 每行显示该餐热量，右侧 **⊕ 点开记录弹窗**（自动预选这一餐）
- **点这一行可展开**看该餐的条目，可改重量（按比例重算）、删除
- 空餐次展开后提示「点右上角 ＋ 添加」

**营养摄入**：三色圆环（蛋白质 / 脂肪 / 碳水）+ 图例，跟随所选日期实时更新。

## 补记历史日期

「记录一餐」卡片顶部有**日期选择器**：

- 用 **‹ ›** 逐日前后切换，或点日期框直接选日期（范围：最近 30 天，不能选未来）
- **「今天」按钮**一键回到今天（已是今天时显示绿色选中态）
- 切到历史日期后，标题变成「**补记 · 10月2日**」，记录写入那一天
- 上方的今日总计卡片与圆环会一起切到该日期，方便对照补记
- 「导出今日 CSV」「清空今日」也随之作用于**所选日期**

## 从对话 / 文档导入记录

如果记录散落在 DeepSeek 对话或某个文档里，「数据与备份」卡片 → **📋 从对话/文档导入记录**，
把内容整段粘进去 → **先检查**（会告诉你解析到几天几条）→ **导入**。

支持的写法（日期单独一行，或写在标题/正文里都可以）：

```
2026-10-01
早餐：鸡蛋 50g 78kcal 蛋白质6g 脂肪5g 碳水1g
午餐 | 牛肉面 | 450g | 680kcal | 蛋白质28g | 脂肪22g | 碳水88g
2026-10-02
米饭 200g 232kcal 蛋白质5g 脂肪0.6g 碳水51g
```

- **日期**：`2026-10-01`、`2026/10/1`、`2026年10月1日`、`10月1日`（沿用前面出现过的年份）、`## 2026-10-01` 都认
- **餐次**：早餐/早饭/早点、午餐/午饭/中餐、晚餐/晚饭、加餐/夜宵/零食/下午茶，中英文皆可；
  分隔符是冒号、竖线还是空格都行；**没写餐次的行会归入「未分餐」**，之后可用餐次下拉归位
- **每行食物**：支持 `名称 | 重量 | 热量 | 蛋白质 | 脂肪 | 碳水`、空格分隔、Markdown 表格行
- **安全设计**：**没有日期就一条都不导入**，避免把对话里的闲聊误写成记录；
  「合计」行不会重复计入；导入前会先给你看解析结果
- 导入时可选 **合并**（保留现有数据、自动跳过重复条目）或 **覆盖**（完全替换）


## 三餐分开记录

- 顶部有 **4 个餐次按钮**，点一下就切换当前餐次；按钮上直接显示该餐已记录的 kcal
- 默认餐次按时间自动判断：10 点前 → 早餐，15 点前 → 午餐，21 点前 → 晚餐，之后 → 加餐
- **今日总计卡片**里有一行「各餐热量」小结，一眼看到三餐分布
- **今日明细**按餐次分组，每组标题带该餐的小计（热量 + 三大营养素）
- **点分组标题可折叠 / 展开**该餐明细（折叠后标题仍显示小计，不会漏看数字）
- **每条记录都有「餐次」下拉菜单**，改一下就自动移动到对应分组 ——
  旧版本那些进「📋 未分餐（旧记录）」的记录，就是靠这个逐个归位到早/午/晚餐
- **导出的 CSV** 含「餐次」列、每餐小计和全天合计
- 旧版本（未分餐）的历史记录会自动归入「📋 未分餐（旧记录）」分组，**不会丢失**

### 其他功能

| 功能 | 说明 |
|---|---|
| 改重量 | 直接改某条的克数，该条的热量和三大营养素**按比例自动重算**，总计同步更新 |
| 手动添一条 | 没有 AI 也能记：名称 + 热量 + 三大营养素 + 重量 |
| 每日目标 | 点右上角 ⚙️ 设置热量 / 蛋白质 / 脂肪 / 碳水目标，热量超标进度条变红 |
| 导出 | 一键把今日记录导出成 CSV（Excel 可直接打开） |
| 历史 | 自动保留最近 30 天 |

### 支持的粘贴格式

解析器很宽容，下面这些写法都能认：

```
米饭 | 200g | 232kcal | 蛋白质5g | 脂肪0.6g | 碳水51g
```

```
白米饭（200克）：热量232kcal，蛋白质5克，脂肪0.6克，碳水51克
```

```
全麦面包 60g 150kcal 蛋白质6g 脂肪2g 碳水27g
```

```
食物名称：牛肉炒饭
重量：400克
热量：720 kcal
蛋白质：24 g
脂肪：26 g
碳水：95 g
```

模型如果返回 JSON 也能解析。带有寒暄、解释的整段回答会自动只挑出数据行。

## 文件说明

| 文件 | 作用 |
|---|---|
| `index.html` | 整个应用（界面 + 逻辑 + 解析器），单文件自包含 |
| `manifest.webmanifest` | 让「添加到主屏幕」显示正确的应用名和图标 |
| `icons/*.png` | 应用图标（火焰），PNG 格式 —— 安卓 Chrome 不接受 SVG 作主屏幕图标 |

| `sw.js` | Service Worker：HTML 走**网络优先**（联网时永远拿最新版），静态资源走缓存优先，断网时回退缓存 |

## 隐私与准确性

- **照片不经过本应用**：直接上传给 DeepSeek，本应用不读取、不上传、不保存任何照片
- 所有记录存在浏览器 `localStorage`，**换手机或清理浏览器数据会丢失**，重要数据请用「导出今日记录」
- AI 对中餐分量的估算是**估算**，误差约 ±20~30%，红烧、油炸类尤其容易低估；混合菜品（盖浇饭、麻辣烫）建议配合文字描述

## 更新应用

改完 `index.html` 后提交，等 1~2 分钟 GitHub Pages 自动重新部署。

**手机上怎么拿到新版**（针对 iOS 主屏幕应用，它没有地址栏也没有下拉刷新）：

1. **正常联网打开应用即可** —— Service Worker 对 HTML 采用网络优先策略，联网时每次打开都是最新版，不需要任何手动操作
2. 若仍看到旧版：打开右下角 **⚙️ → 🔄 检查更新**，按提示确认即可
3. 极端情况下（应用图标缓存、iOS 顽固缓存）：**删掉主屏幕图标重新添加一次**。记录存在 localStorage，不会丢失

应用内 **⚙️ 设置面板右上角显示当前版本号**，可用来确认是否已更新到最新版。
